# Resilient Compiler with Intelligent Error Recovery

An end-to-end, resilient compiler design project implemented in modern C++17. The compiler features lexical analysis, recursive-descent parsing with intelligent multi-strategy syntax error recovery, scope-aware semantic analysis, three-address code (TAC) intermediate representation, constant-folding optimization, and a target bytecode virtual machine (VM).

---

## 1. Compiler Pipeline Architecture

The compiler implements a complete 7-stage pipeline:

```text
Source Code (.txt)
       │
       ▼
[1. Lexer] ─────────────► Tokens (with line & column tracking)
       │
       ▼
[2. Parser & Recovery] ──► Intelligent Error Recovery (Insertion / Deletion / Panic)
       │
       ▼
[3. AST Generator] ─────► Abstract Syntax Tree (Object-Oriented, Null-Safe)
       │
       ▼
[4. Semantic Analyzer] ─► Symbol Table (Nested Scopes, Type Checking, Redeclaration)
       │
       ▼
[5. IR Generator] ──────► Three-Address Code (TAC) with Temporaries & Labels
       │
       ▼
[6. TAC Optimizer] ─────► Constant Folding, Propagation & Dead Code Elimination
       │
       ▼
[7. Code Generator & VM]► Stack Bytecode Disassembly & Execution on Virtual Machine
```

## 2. Implemented Features

### Phase A: Resilient Front End
* **Lexer**: Tokenizes keywords (`int`, `float`, `bool`, `if`, `else`, `while`, `print`), identifiers, integer/floating-point literals, arithmetic operators (`+`, `-`, `*`, `/`, `%`), comparison operators (`<`, `>`, `<=`, `>=`, `==`, `!=`), logical operators (`&&`, `||`), single-line comments (`//`), and delimiters (`(`, `)`, `{`, `}`, `;`).
* **Intelligent Error Recovery**:
  * **Token Insertion**: Synthesizes missing delimiters (e.g., missing `;` before statements, missing `)` before `{`) and missing expressions (e.g. `int x = ;` inserts default `0`).
  * **Token Deletion**: Detects and discards extraneous redundant tokens (e.g., `x = 10;;`).
  * **Panic Mode**: Skips illegal tokens until safe statement boundaries (`semicolon` or `}`) when single-token repairs are non-viable.
  * **Lookahead Cost Scoring**: Context-aware [RecoveryScorer](src/recovery/RecoveryScorer.h) evaluates candidate repair strategies using parser context and 1-token lookahead rather than fixed tables.

### Phase B: Symbol Table & Semantic Analysis
* **Hierarchical Scope Management**: Stack-based scope frames supporting block scopes (`{ ... }`) and variable shadowing.
* **Semantic Verification**:
  * Detects undeclared identifiers.
  * Detects duplicate variable declarations within the same scope.
  * Enforces static type compatibility for assignments and declarations (`int`, `float`, `bool`).
  * Validates operator type constraints (e.g., `%` restricted to integers; relational/logical operands checked).
  * Continues analysis across subsequent statements while returning a non-zero exit code upon semantic failure.

### Phase C: Intermediate Code Generation (TAC)
* Emits linear Three-Address Code with clean syntax:
  * `t0 = y * 2`
  * `result = t1`
  * `ifFalse t2 goto L1`
  * `print result`

### Phase D: Code Optimization
* **Constant Folding**: Evaluates constant arithmetic and relational operations at compile time (`2 + 3 * 4` $\to$ `14`).
* **Constant Propagation**: Propagates constant literals through straight-line basic blocks.
* **Dead Code Elimination**: Eliminates self-assignments (`x = x`) and unreferenced temporaries.

### Phase E: Target Bytecode Virtual Machine (VM)
* **Bytecode Instructions**: `PUSH_CONST`, `LOAD_VAR`, `STORE_VAR`, `ADD`, `SUB`, `MUL`, `DIV`, `MOD`, `EQ`, `NE`, `LT`, `GT`, `LE`, `GE`, `AND`, `OR`, `NEG`, `JUMP`, `JUMP_IF_ZERO`, `PRINT`, `HALT`.
* **VM Interpreter**: Executes the generated bytecode on an internal operand stack and memory store, displaying outputs and final variable states.

## 4. Compilation & Build Instructions

### Prerequisites
* GCC (g++) with C++17 support (MinGW-w64 on Windows).

### Build Command (from project root)
```powershell
g++ -std=c++17 -Wall -Wextra src/main.cpp src/lexer/Lexer.cpp src/ast/AST.cpp src/parser/Parser.cpp src/recovery/RecoveryManager.cpp src/recovery/RecoveryScorer.cpp src/semantics/SymbolTable.cpp src/semantics/SemanticAnalyzer.cpp src/ir/TAC.cpp src/ir/IRGenerator.cpp src/optimizer/Optimizer.cpp src/vm/VM.cpp src/vm/CodeGenerator.cpp -o resilientc.exe
```

---

## 5. Command-Line Interface (CLI) Usage

Run the compiler on any source file or use inspection flags:

```powershell
# Run the complete pipeline (Lexer, Parser, Semantics, TAC, Optimizer, VM)
.\resilientc.exe tests/12_end_to_end_exec.txt

# Inspect specific stages
.\resilientc.exe tests/01_valid_program.txt --ast       # Display AST only
.\resilientc.exe tests/01_valid_program.txt --symbols   # Display Symbol Table & Semantics
.\resilientc.exe tests/01_valid_program.txt --tac       # Display Three-Address Code
.\resilientc.exe tests/01_valid_program.txt --opt       # Display Optimization diff
.\resilientc.exe tests/01_valid_program.txt --target    # Display Bytecode Disassembly
.\resilientc.exe tests/01_valid_program.txt --run       # Execute on VM
.\resilientc.exe tests/01_valid_program.txt --all       # Print all stages sequentially

# Run built-in demonstration (no arguments)
.\resilientc.exe
```

## 6. Automated Test Suite

Run the full automated test suite containing 14 test cases:

```powershell
powershell -ExecutionPolicy Bypass -File .\run_tests.ps1
```

All 14 tests verify expected exit codes and pass automatically:
* Tests 1–6: Syntax error recovery & valid programs (Exit code 0).
* Tests 7–9: Semantic rejection tests for undeclared, duplicate, and mismatched types (Exit code 1).
* Tests 10–14: Optimization, nested scopes, fibonacci, and loops on VM (Exit code 0).

## 7. Sample Program & Output

### Input (`examples/fibonacci.txt`):
```c
int count = 6;
int t1 = 0;
int t2 = 1;
int next = 0;

while (count > 0) {
    print t1;
    next = t1 + t2;
    t1 = t2;
    t2 = next;
    count = count - 1;
}
```

.\resilientc.exe examples/fibonacci.txt --run
